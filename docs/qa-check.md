re-checked by hand instead and carries its disposition. Fixes were verified by the extended Playwright suite
(see README, "Check results") and a second responsive sweep.

## Highest-risk untested

1. Production build served by `next start` behind a real host: all checks ran against the dev server (the build itself passes; the demo URL must be clicked once after deploy).
2. Real phones and Safari: every browser check used headless Chromium; touch behaviour, iOS Safari's 100dvh and font rendering are unverified.
3. The debounce race under slow networks: the fix merges state deterministically, but only the deterministic variant (chip within 300 ms) has an automated test.

## Recommended tests (added in this pass unless marked TODO)

- e2e/catalog-navigation.spec.ts: back button · chip within debounce · page clamp in URL · optimistic page highlight · error toolbar · accessible names · covers on every page · branded 404
- e2e/cart.spec.ts: seeded totals · remove · empty state + Browse books · add once / already in cart · DEV10 · invalid and empty code · checkout stub · persistence
- e2e/responsive.spec.ts: cart filled at the 10 WM widths, cart empty at the key widths, element-overflow check in addition to scrollWidth

## Manual QA for a human

- Open the demo URL once after deploying and click every link in the header, the cards, the pagination and the footer.
- Compare /books/list and /cart side by side with the Figma frames at 1440 and 375 (spacing, type weight, chevron colours).
- On a phone: add a book, open the cart, remove it, apply DEV10, press Proceed to checkout; watch the toasts stay inside the screen.
- Keyboard only: Tab through header, chips, sort (open it with Enter, change with arrows), cards, pagination, cart Remove/Apply/checkout.
- Switch the OS to dark mode and reload the 404 page and the catalog: only the 404 used to go black; both should stay branded.
